Auto Reply Module Product Concept

1. Objective

The Auto Reply module allows organizations to configure automatic responses for incoming customer messages across their integrated communication channels such as Gmail, Outlook, WhatsApp and other supported channels.

The objective is to ensure customers receive a timely response when a salesperson is unavailable, while still allowing the organization to control when, where and how automatic replies are sent.

Core capabilities

Product principle

The backend and core engine can support future automation capabilities, while the initial user interface remains simple. Advanced controls can be introduced progressively without changing the fundamental product concept.

4. Response Timing & Trigger

The Auto Reply is triggered when a customer message remains unanswered by a salesperson for the configured period.

10:00 AM
Customer sends message
"Hi, is this property still available?"
↓
10:00–10:30
No salesperson response.
↓
10:30 AM
Auto Reply is triggered

Important behavior

If the salesperson responds before the configured waiting period, the Auto Reply should not be sent.
Customer ↓ Customer Message ↓ Start Waiting Period ↓ Did Salesperson Respond? ├── YES → Stop └── NO → Send Auto Reply

The timing should be associated with the latest customer message that remains unanswered rather than simply relying on the last activity timestamp of the conversation.

5. Reply Type

Option A — Static Reply

The organization defines a fixed response that will be sent whenever the Auto Reply conditions are satisfied.

Example:

"Thank you for reaching out. Our sales team is currently unavailable and will get back to you shortly."

Option B — AI Reply

The organization can use the existing AI Draft Generation capability to generate a contextual response.

The existing AI Draft Generation capability can be reused as the response-generation layer instead of creating a separate AI engine.

6. Important Business Rules

Salesperson has already responded

Customer → Message Salesperson → Response Auto Reply → NOT triggered

This prevents duplicate or confusing responses.

Multiple customer messages

10:00 Customer → Hi 10:05 Customer → Is this available? 10:10 Customer → Anyone there?

The system should consider the latest unanswered customer activity when determining the response timing.

Prevent automated response loops

The system must distinguish between customer messages, salesperson messages and messages generated by the Auto Reply system.

An Auto Reply message must never trigger another Auto Reply.

Conversation handling

Future versions can use conversation status such as Open, Waiting for Salesperson, Closed or other organization-defined statuses to determine whether automation should operate.

11. Product Direction

Flexible backend. Simple user experience. Progressive capability.

The Auto Reply module should provide a simple configuration experience initially while keeping the underlying product architecture flexible enough to support advanced automation capabilities in future releases.

Core concept

AUTO REPLY │ ┌────────────┼────────────┐ │ │ │ Trigger Conditions Response │ │ │ Delay Channel Static Message Status AI Schedule Future Limits │ ↓ Channel Adapter │ ┌───────────┼───────────┐ ↓ ↓ ↓ Gmail Outlook WhatsApp

Key principle

The product should not expose every possible configuration on day one. The initial release should focus on the core user need: automatically responding to an unanswered customer message.

As business requirements evolve, advanced controls can be introduced through additional settings without fundamentally changing the Auto Reply experience.

Expected outcome: A scalable Auto Reply capability that is easy for organizations to configure today and flexible enough to support increasingly sophisticated automation in future releases.
